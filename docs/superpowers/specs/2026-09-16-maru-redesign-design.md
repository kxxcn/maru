# 마루 UI 전면 개편 설계 문서

작성일: 2026-09-16
시각 자료: `docs/design/maru-redesign-2026.html` (같은 내용의 Artifact: https://claude.ai/artifact/6rRxV7M7uwFESJ9dJ7gbyf)
이 문서는 HTML 제안서의 결정 사항을 구현 가능한 명세로 옮긴 것이다. 두 문서가 다르면 이 문서를 따른다.

## 1. 배경과 목표

마루는 결혼 준비 체크리스트와 신랑/신부 지출 기록 앱이다. 기능은 충실하지만 레이아웃 XML 69개, 컬러 리소스 113개, 커스텀 뷰 13개에 화면마다 다른 시각 언어가 쌓여 있다.

목표:
- 색, 형태, 타이포그래피를 토큰 12개와 규칙 하나로 통일한다.
- 홈, 체크리스트, 지출 입력, 더보기의 정보 구조를 정리한다.
- 광고 지면을 줄이고 프리미엄 판정을 한 곳으로 모은다.
- 데이터 모델(User, Task, Account, Day)과 Room 스키마는 바꾸지 않는다.

## 2. 결정 사항 (2026-09-16)

| 항목 | 결정 |
|---|---|
| 홈 배너 광고 | 제거 (A안) |
| 전면 광고 | 지출 저장, 편집 다이얼로그 모두 저장당 노출 유지 |
| 완료 처리 | 잔금 0원 자동 완료(토글)와 체크 원 수동 완료 둘 다 |
| 체크리스트 정렬 | 진행 중, 준비 전, 완료 묶음 순. 묶음 안에서는 사용자 순서(priority) 유지 |
| 서체 | 안드로이드 기본 서체. 번들하지 않음 |
| 항목 아이콘 | 기존 18개 자산 유지. 타일 배경과 틴트만 새 토큰 |
| Material Components | 의존성 추가하지 않음. 세그먼트와 하단 시트는 자체 구현 |
| 잔금 마감일 | 필드 추가하지 않음. 기록일 표시 |

## 3. 범위

포함:
- 테마와 리소스 정리 (토큰, 서체 제거, 디데이 색 제거)
- 홈, 체크리스트, 지출 입력, 완료 상태, 디데이, 디데이 추가, 타임라인, 더보기, 등록(온보딩) 화면
- 나머지 화면에 시스템 적용 (7장)
- 광고 지면 재배치와 프리미엄 판정 통일
- 정렬과 완료 규칙 변경

제외:
- Room 스키마 변경, 마이그레이션
- 새 기능 (마감일, 알림 종류 추가 등)
- Material Components 도입, Compose 전환
- 서버(Firebase) 구조 변경

## 4. 디자인 시스템

### 4.2 서체와 타입 스케일

시스템 기본 서체(Roboto, Noto Sans CJK KR). 굵기와 크기로만 위계를 만든다. 숫자는 `fontFeatureSettings="tnum"`.

| 역할 | 크기 | 굵기 | 자간 | 예 |
|---|---|---|---|---|
| 디데이 숫자 | 68sp (홈), 46sp (디데이 화면 상단) | 700 | -0.02em | D-129 |
| 금액 대 | 34sp | 500 | -0.01em | 4,700만원 |
| 금액 중 | 26sp | 500 | | D-38, 1,200만원 |
| 화면 제목 | 26sp | 700 | -0.01em | 체크리스트 |
| 섹션 제목 | 16sp | 600 | | 예산 |
| 본문 | 15sp | 400 / 600 (강조) | | 웨딩홀 |
| 보조 | 13.5sp | 500 | | 잔금 1,200만원 |
| 메타 | 12.5sp | 500 | | 6월 2일 기록 |

최소 글자 크기 12sp. `MaruTextView`, `VerticalTextView`, `ArgProgressView`의 Typeface 로딩을 제거하고 `assets/nixgon.ttf`, `res/font/nixgon.ttf`, `res/font/font_recipe.ttf`를 삭제한다.

### 4.3 형태와 간격

- 라디우스: 카드 20dp, 입력 필드와 아이콘 타일 14dp, 버튼과 칩 pill, 하단 시트 상단 28dp.
- 그림자: 하단 시트와 FAB만. 나머지는 1dp `maru_line`과 표면 2단계로 구분.
- 화면 좌우 여백 20dp. 섹션 사이 26dp, 섹션 제목과 내용 사이 12dp.
- 목록 행: 세로 여백 14dp, 최소 높이 72dp, 아래 1dp 선. 마지막 행은 선 없음.
- 터치 영역 최소 48dp (체크 원은 26dp 시각 크기에 48dp 터치 영역).
- 아이콘 타일 44dp, 안쪽 아이콘 22dp. 하단 탭 높이 70dp 유지(현재 값).

### 4.4 아이콘

- 항목 아이콘 18개(`ic_greeting` 등)는 유지. 타일 배경만 상태별로: 준비 전 `maru_surface_2` + 틴트 `maru_ink_2`, 진행 중 `maru_yellow_tint` + `maru_yellow_ink`, 완료 `maru_done` 틴트 + `maru_done`.
- UI 아이콘(뒤로, 추가, 편집, 체크, 화살표)은 기존 벡터 드로어블 유지, 틴트만 토큰으로.

### 4.5 접근성

- 텍스트 대비: 종이 위 `maru_muted` 4.6:1, `maru_ink_2` 6.9:1, 옐로 위 먹 10.6:1.
- 모든 아이콘 버튼에 contentDescription.
- 체크 원, 세그먼트, 토글은 상태를 색과 함께 형태(체크 표시, 배경 이동)로도 전달.

## 5. 화면 명세

각 화면은 "구성", "동작", "데이터"로 적는다. 시각은 HTML 목업을 따른다.

### 5.1 홈 (HomeFragment)

구성 (위에서 아래로):
1. 인사 행: "{이름}님, 안녕하세요", 오른쪽 알림 아이콘 버튼(공지사항으로 이동).
2. 디데이 카드 (옐로): "결혼식까지", D-N 68sp, "YYYY년 M월 D일 요일", 하단에 체크리스트 진행 바와 "체크리스트 완료/전체".
   - 결혼식이 지났으면 숫자 대신 "결혼을 축하합니다" (기존 문구 유지).
3. 예산: 사용 금액 34sp + "/ 전체 예산", 청/홍 분담 바, 범례(신랑 금액, 신부 금액, 남은 예산). "자세히"는 체크리스트 탭으로.
4. 남은 잔금: remain > 0인 항목을 잔금 큰 순으로 최대 1개 표시, "외 N건" 링크. 행: 아이콘 타일, 항목명, "{총지출} 지불, {기록일} 기록", 오른쪽 잔금 금액.
   - remain > 0인 항목이 없으면 섹션 숨김.
5. 디데이: 가로 스크롤 칩. 결혼식 외 사용자 디데이를 날짜순. 없으면 "디데이 등록하기" 칩 하나.

제거: 환영 카드의 Lottie, 지출 카드의 파이 차트(MPAndroidChart), 체크리스트 요약 카드의 원형 진행(CircleProgressView), 우주라이트 배너(더보기로 이동), 배너 광고.

데이터: `Summary`의 기존 계산 프로퍼티 사용. 금액은 만원 단위 표기(`ConvertUtils`에 만원 포맷 추가).

### 5.2 체크리스트 (TasksFragment)

구성:
1. 제목 "체크리스트" 26sp, 부제 "{전체}개 중 {완료}개 완료", 오른쪽 정렬 편집 버튼(기존 SortFragment).
2. 진행 바 (완료/전체, `maru_done`).
3. 세그먼트: 전체(N), 진행 중(N), 완료(N). 마지막 선택 기억(기존 `PreferenceUtils.taskFilterType`).
4. 목록 행 (단일 레이아웃 `task_item_row.xml`):
   - 체크 원 (26dp, 완료면 `maru_done` 채움 + 흰 체크)
   - 아이콘 타일 (상태별 색)
   - 이름 15sp 600, 메타 12.5sp
   - 진행 중: "{총지출} · 잔금 {remain}" 대신 두 값을 10dp 간격으로 나열, 아래 청/홍 분담 바(최대 180dp)
   - 준비 전: "지출 기록하기"
   - 완료: "{총지출}  {완료일} 완료" (account 없으면 "생략")
   - 오른쪽 chevron
5. FAB(+): 체크리스트 추가 다이얼로그(기존 EditDialogFragment, REGISTER_TASK).
6. 광고 슬롯(목록형): 5절 참고. 4번째 행 뒤, 이후 10행 간격, 최대 2개.

동작:
- 행 탭: 지출 입력 시트 열기.
- 체크 원 탭: `TaskDao.updateTask(id, !isCompleted)`. 완료 해제 시 remain은 그대로 둔다.
- 정렬: `sortedWith(compareBy({ stateRank }, { priority }))`. stateRank: 진행 중 0, 준비 전 1, 완료 2. 진행 중 = 미완료이고 account.remain > 0. 준비 전 = 미완료이고 account 없음 또는 remain == 0.
- 빈 상태: 필터별 문구 유지("진행 중인 체크리스트가 없어요" 등), Lottie 대신 아이콘 타일과 문구.

### 5.3 지출 입력 (InputFragment를 하단 시트로)

구성 (DialogFragment, 하단 고정, 배경 스크림 50%):
1. 손잡이, 아이콘 타일 + 항목명 + "{기록일} 처음 기록" (기록 없으면 "아직 기록 없음"), 닫기.
2. 총 지출 (신랑 + 신부) 32sp.
3. 필드 3개: 신랑(청 점), 신부(홍 점), 잔금(옐로 점). 탭하면 선택 상태(테두리 먹). 기본 선택은 신랑.
4. 단위 칩 4개: +1만, +10만, +100만, +1000만. 선택된 필드에 더한다(기존 `InputFilterType` 로직).
5. 키패드 3x4: 1~9, 00, 0, 지우기. 선택된 필드에 직접 입력.
6. 토글 "잔금이 0원이 되면 완료로 표시" (기본 켬, `PreferenceUtils.autoComplete`).
7. 저장하기 (옐로 pill, 전체 폭).

동작:
- 저장: 기존 `InputViewModel.complete()` 흐름 유지. 신랑과 신부 모두 0이면 기존 메시지.
- 저장 성공 후: 프리미엄이 아니면 전면 광고(기존 흐름), 그 뒤 완료 상태 화면.
- 자동 완료: 토글이 켜져 있고 remain == 0이면 `isCompleted = true` (기존 `LocalDataSource.saveAccount` 로직). 토글이 꺼져 있으면 remain == 0이어도 완료로 바꾸지 않는다. 이미 수동 완료된 항목은 저장해도 완료 상태를 유지한다.
- 기존 +/- 스텝퍼와 전체 화면 InputFragment는 제거.

### 5.4 완료 상태 (StatusFragment)

구성: 제목 "차근차근 하나씩 준비하세요!" 유지, 원형 진행(자체 드로잉 `ArcProgressView` 유지, 색만 토큰), 완료/전체 숫자, "다음 할 일" 한 줄(진행 중 첫 항목), 닫기 버튼(옐로 pill). Lottie `animation_complete` 유지(이 화면만).

### 5.5 디데이 (DaysFragment, DaysAddFragment)

목록:
1. 뒤로, 추가 버튼. 제목 "디데이", 부제 "결혼식과 우리가 기다리는 날들".
2. 상단 고정 옐로 카드: "결혼식", 날짜, D-N 46sp. `User.wedding`에서 계산.
3. 행: 내용 15.5sp 600, 날짜 12.5sp, 오른쪽 숫자 26sp. `REMAIN` 타입은 D-N / D+N / D-Day, `COUNT` 타입은 "N일"에 "날짜수" 칩. 지난 날(D+)은 `maru_muted`.
4. 롱프레스 삭제 다이얼로그 유지.
5. 빈 상태: 아이콘 타일, "아직 등록한 디데이가 없어요", 설명, "디데이 등록하기" 먹 버튼.

추가 화면: 기존 구성(내용 입력, 타입 2택, 날짜 선택, 등록) 유지. 색 선택은 제거하고 `Day.color`는 저장하지 않는다(필드는 남기고 0 저장). `day_background0~17` 색 리소스 삭제.

### 5.6 타임라인 (TimelineFragment)

구성: 뒤로, 제목 "타임라인", 부제 "결혼식 D-180부터 당일까지, 시기별로 할 일". 세로 레일 위 시기 그룹(D-180, D-150, D-120, D-90, D-60, D-30, D-14, D-Day). 각 그룹 제목 17sp 600 + 해당 날짜(결혼식 기준 계산, 예 "9월 25일까지").

동작:
- 오늘 위치: 현재 D값보다 작은 첫 그룹에 "오늘 D-N" 옐로 칩. 지난 그룹은 완료색 점과 체크 아이콘.
- 항목 탭: 기존 가이드 문구를 접기/펼치기. 한 번에 여러 개 열 수 있다.
- 기존 `TimelineItem`, 문자열 리소스 재사용. 분홍 카드 배경 제거.

### 5.7 더보기 (MoreFragment)

구성:
1. 제목 "더보기".
2. 프로필 카드: 아바타(이름 첫 글자, 옐로), 이름, "{결혼일}, 예산 {금액}". 탭하면 설정 > 프로필 편집(기존 EditFragment).
3. 준비 가이드 (3x2 타일): 타임라인, 결혼식 순서, 드레스, 턱시도, 한복, 반지.
4. 도구 (행): 디데이, 셀프웨딩 촬영 명소, 백업과 복원(프리미엄 확인 흐름 유지).
5. 프리미엄 카드 (옐로 틴트): "프리미엄", "광고 없이 쓰고, 백업과 복원을 열어요", 3,000원. 프리미엄이면 "프리미엄 이용 중"으로 바꾸고 가격 숨김.

## 6. 동작 규칙 요약

- 상태 판정: 완료 = `Task.isCompleted`. 진행 중 = 미완료이고 `account.remain > 0`. 준비 전 = 그 외 미완료.
- 정렬: 상태 묶음(진행 중, 준비 전, 완료) 안에서 `priority` 오름차순.
- 자동 완료: 토글 켬이고 저장 시 remain == 0이면 완료. 토글은 앱 전체 설정(PreferenceUtils).
- 수동 완료: 체크 원 탭으로 토글. 완료 해제해도 account는 유지.
- 금액 표기: 홈과 목록은 만원 단위(1만원 미만은 원 단위), 입력 시트와 등록은 원 단위 콤마.
- 날짜 표기: 같은 해는 "M월 D일 요일", 다른 해는 "YYYY년 M월 D일 요일".
- 디데이 셈법: `REMAIN` D-N / D+N / D-Day, `COUNT` N일(등록일을 1일로).

## 10. 검증 기준

- 컴파일과 기존 유닛 테스트 통과 (`AdHelperTest` 포함). `TasksAdapter.makeItems` 광고 위치와 정렬은 유닛 테스트 추가: 18개 항목에서 광고 인덱스가 정확히 두 곳(4번째, 14번째 행 뒤)인지, 프리미엄이면 0개인지, 묶음 순서와 묶음 내 priority가 지켜지는지.
- 완료 규칙 유닛 테스트: 토글 켬/꺼짐과 remain 0/양수 4가지 조합.
- 에뮬레이터 스크린샷: 8개 화면을 라이트와 다크에서 각각 확인. 비교 기준은 HTML 목업.
- 광고: 테스트 유닛 ID로 체크리스트 2개, 더보기 1개, 전면 2종 노출 확인. 프리미엄 계정(로컬 `premium = true`)에서 5곳 모두 미노출 확인.
- 대비: 메타 텍스트와 배경 조합 4.5:1 이상을 색 값으로 확인.
- 회귀: 정렬 편집(드래그), 백업/복원, 결제 흐름이 그대로 동작.

## 11. 단계 제안

상세 계획은 별도 문서(writing-plans)로 만든다. 순서만 적는다.

1. 토큰과 테마: colors, styles, 서체 제거, 디데이 색 제거. 이 단계만으로 앱 전체 색이 바뀌고 회귀가 없어야 한다.
2. 공통 컴포넌트: 세그먼트, 체크 원, 아이콘 타일, 분담 바, 옐로/고스트/먹 버튼 스타일, 광고 슬롯 뷰.
3. 체크리스트 + 지출 입력 시트 + 완료 상태 (정렬, 완료 규칙, 광고 규칙 포함).
4. 홈 (배너 제거, 남은 잔금, 디데이 칩).
5. 더보기 + 프리미엄 판정 통일 + 광고 게이트.
6. 디데이, 타임라인, 등록.
7. 나머지 화면 적용, 미사용 뷰와 의존성 삭제, Lottie 정리.

각 단계 끝에 컴파일, 관련 유닛 테스트, 해당 화면 스크린샷 확인.
